# OpenAI Codex CLI 工具介绍

> OpenAI 出品的终端 AI 编程助手  
> 更新日期：2026-05-11

---

## 1. 是什么
OpenAI Codex CLI 是 OpenAI 推出的开源终端 AI 编码代理，主打安全沙箱和审批机制。
它强调在终端中完成编码任务，同时把执行边界、权限范围和自动化风险控制清楚。
如果你希望 AI 能动手改代码，但又不能默认拿到过高权限，Codex CLI 的定位会比较合适。

典型入口：
```bash
codex
```
```bash
codex "为当前 iOS 工程补一个统一错误提示层"
```

可解决的问题：
- 在终端里执行编码任务
- 用审批模式控制修改权限
- 在受限环境里跑自动化任务
- 为 CI/CD 生成可重复执行的流程
- 在长任务中保留恢复能力

## 2. 安装方式
### 2.1 环境要求
- macOS / Linux
- Node.js 环境，或可用 Homebrew
- OpenAI API Key，或可用的 ChatGPT Plus/Pro

### 2.2 npm 安装
```bash
npm i -g @openai/codex
```

### 2.3 Homebrew 安装
```bash
brew install --cask codex
```

### 2.4 检查版本
```bash
codex --version
```

### 2.5 配置凭证
```bash
export OPENAI_API_KEY="your_api_key"
```
然后启动：
```bash
codex
```

## 4. 核心能力
### 4.1 三级审批模式
Codex CLI 的审批模式是核心特性之一，常见分层包括：
- `suggest`
- `auto-edit`
- `full-auto`

可以简单理解为：
- `suggest`：只给建议，不直接大范围执行
- `auto-edit`：允许自动修改，但仍保留边界
- `full-auto`：更高自动化程度，适合受控环境

### 4.2 沙箱执行
主打安全沙箱和受限执行环境，重点包括：
- 网络隔离
- 文件系统受限
- 审批后再执行高风险动作

这类设计更适合：
- 自动修复脚本
- CI/CD 中的代码生成
- 受控目录内的批量改动

### 4.3 多模型支持
支持多模型选择，常见示例包括：
- GPT-5.5
- GPT-5.4
- o4-mini

选择思路：
- 复杂改动：高能力模型
- 高频批任务：成本更稳的轻量模型
- 流水线脚本：固定单一模型便于行为稳定

### 4.4 非交互 exec 模式
`--exec` 适合在没有人工交互的环境中直接运行任务。
```bash
codex --exec "检查当前目录所有 Markdown 是否缺少一级标题"
```
```bash
codex --exec "为本次提交生成 release notes 草稿"
```
适合：
- CI/CD
- Git hook
- 批处理脚本
- 自动检查任务

### 4.5 代码审查
支持通过 `codex review` 做代码审查。
```bash
codex review
```
典型使用方式：
- 提交前先看风险点
- 检查边界条件
- 审查是否存在重复逻辑
- 看改动是否超出目标范围

### 4.6 断点续做
任务较长或需要中断后继续时，可以使用恢复能力。
```bash
codex resume
```
这对长链路任务很重要，例如较大的代码迁移、分阶段文档生成、按目录逐步改造。

### 4.7 开源项目
Codex CLI 以开源项目形式提供：
```text
openai/codex
```
这意味着你可以更方便地查看实现思路、跟踪版本变化、评估是否适合接入团队流程。

## 6. 定价模式
Codex CLI 常见使用方式有两类。

### 6.1 ChatGPT Plus / Pro
适合个人直接使用终端工具，降低单独管理 API 的成本。

### 6.2 API Key
适合自动化、脚本化、流水线接入。

选择建议：
- 个人试用：先用订阅
- 工具链集成：优先 API Key
- 高频批任务：重点评估按量成本

## 7. 配置文件
### 7.1 用户级目录
```text
~/.codex/
```
通常用于保存用户级配置、缓存或运行态信息。

### 7.2 项目级指令文件
```text
codex.md
```
适合放：
- 项目背景
- 审批策略说明
- 目录边界
- 输出格式要求
- 验证命令

最小示例：
```md
# Codex Project Rules

- 仅修改 app/ 和 docs/ 目录
- 生成 Swift 示例时统一包含错误处理
- 输出前先总结风险点
- 涉及移动端页面时说明状态流转
```

### 7.3 推荐配置思路
如果更重视安全控制，建议把这些内容写清楚：
- 哪些目录允许改
- 哪些命令只能建议不能执行
- 哪些任务必须先 review 再落地
- 哪些校验命令必须在结束前执行

## 8. 最小实践路线
### 第一步：确认安装和凭证
```bash
codex --version
```
```bash
echo $OPENAI_API_KEY
```

### 第二步：进入仓库启动交互
```bash
cd your-project
codex
```

### 第三步：先用只读任务熟悉输出
```bash
codex "解释当前移动端工程的目录结构和模块分工"
```

### 第四步：再尝试小范围改动
```bash
codex "为现有页面补一个空状态占位视图，并保持现有行为"
```

### 第五步：最后补项目级规则
```text
codex.md
```

这样更容易把 Codex CLI 用在“可控自动化”场景，而不是直接把所有权限一次性放开。
