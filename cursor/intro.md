# Cursor 使用指南
> VS Code 深度定制的 AI 编辑器  
> 更新日期：2026-05-11

---
## 1. 是什么
Cursor 是面向开发者的 AI 编辑器，基于 VS Code fork，把补全、对话、代码编辑、Agent 能力直接放进编辑器主流程。
它的核心定位不是“带聊天框的编辑器”，而是让 AI 成为编辑器的一等公民：
- 写代码时用 `Tab` 做连续补全
- 改代码时用 `Cmd + K` 做局部编辑
- 理解项目时用 `Chat` 做上下文问答
- 跨文件改造时用 `Composer` / `Agent` 做多步执行
它也是当前最主流的 AI 编码产品之一，优势在于迁移成本低、多模型可切换、GUI 交互友好、多文件修改体验成熟。
一句话理解：**Cursor = 编辑器工作流 + 大模型能力 + 工程上下文。**

## 2. 安装方式
### 2.1 下载地址
官网：<https://cursor.sh>
常见安装包：`macOS .dmg`、`Windows .exe`、`Linux` 对应发行版安装包。

### 2.2 从 VS Code 迁移
首次启动通常会提供迁移向导，可导入：
- Settings
- Keybindings
- Themes
- Extensions
已有 VS Code 用户基本不需要重新建立编辑器习惯。

### 2.3 系统要求
常见要求：
- macOS / Windows / Linux
- 稳定网络连接
- 可登录 Cursor 账号
- 本地具备正常开发环境（Git、语言运行时、包管理器等）
注意：Cursor 不替代本地编译器、SDK 和依赖管理工具。

### 2.4 首次启动建议
第一次打开后，优先完成：
1. 登录账号
2. 导入 VS Code 配置
3. 打开真实项目而不是空目录
4. 等待 codebase index 建立完成
5. 检查默认模型与隐私选项

## 3. 快速上手
### 3.1 打开项目
和 VS Code 一样，直接 `Open Folder` 或 `Open Workspace` 即可。
第一次进入项目时，建议先让它完成索引。索引完成后：
- `@codebase` 检索更准
- Chat 回答更稳定
- 跨文件修改更容易命中正确位置

### 3.2 第一次用 `Cmd + K`
最适合处理**小范围改动**。
```text
提取错误处理逻辑，保持返回结构不变
```
规则：选中代码再 `Cmd + K` 改当前片段；不选中直接 `Cmd + K` 在光标处生成代码。

### 3.3 第一次用 `Cmd + L`
`Cmd + L` 打开 Chat，适合解释当前文件、找调用链、生成测试、分析报错和输出修改方案。
```text
@file src/api/client.ts 解释这个文件的职责、主要依赖和潜在风险
```

### 3.4 第一次用 Composer / Agent
当需求超出“改一段代码”时，用多文件工作流更合适。
适合场景：
- 新增完整模块
- 同时改多个文件
- 自动生成实现 + 测试 + 文档
- 让 AI 读文件、写文件、跑命令后再回报
入门建议：
```text
为当前项目新增一个最小可用的 API client，包含类型定义、错误处理和测试骨架
```
先做小任务，再逐步提高 Agent 的自主范围。

## 4. 核心功能
### 4.1 Tab 补全
这是 Cursor 使用频率最高的能力。
特点：
- 支持单行和多行预测
- 能结合当前文件上下文续写
- 对重复样板代码特别高效
常用操作：`Tab` 接受建议，`Esc` 拒绝建议。
适合补全重复模式、续写函数体、快速补测试样板；不适合复杂架构设计和跨文件大改。

### 4.2 `Cmd + K`（行内编辑）
这是最稳定、最可控的局部编辑入口。
- 选中代码再 `Cmd + K`：针对当前片段改写
- 不选中直接 `Cmd + K`：在光标位置生成代码
推荐写法：明确范围、约束和禁止改动项。
```text
只优化错误处理和日志，不改函数签名，不改返回值结构
```

### 4.3 Chat（`Cmd + L`）
Chat 是侧边栏问答入口，适合做解释、分析、规划、定位。
典型用途：
- 解释文件职责
- 查某个 symbol 的使用方式
- 生成重构方案
- 分析报错与修复路径
- 写 commit message / PR 描述草稿

### 4.4 Composer / Agent
这是 Cursor 的多文件执行能力。旧资料常见 `Composer` 叫法，新版本更多把这类能力统一到 `Agent` 视角。
它和普通 Chat 的区别在于：
- 不只是回答
- 还能跨文件修改
- 可按步骤推进任务
- 部分模式下可执行终端命令
建议先缩小目标目录，明确禁止改动的部分，一次只交付一个清晰目标。

### 4.5 `@` 上下文引用
这是让 Cursor 回答更准的关键能力。
常用引用：
- `@file`：引用单个文件
- `@folder`：引用目录
- `@codebase`：在整个项目做语义级检索
- `@web`：补充网络信息
- `@docs`：引用文档或官方资料
推荐思路：问题越具体，引用越精确；先缩范围，再提要求。

### 4.6 多模型支持
Cursor 的一个重要优势，是同一编辑器里可切不同模型。
常见搭配：
- 日常补全：低延迟模型
- 代码解释与重构：均衡模型
- 长上下文分析：高能力模型
- 高成本任务：按需切到更强模型
经验法则：补全优先速度，重构优先能力，Agent 优先长上下文和工具协同。

## 5. 项目规则配置
### 5.1 `.cursorrules` / `.cursor/rules`
规则文件的作用，是把“团队习惯”变成“AI 默认行为”。
可以把它理解为：
- 项目级提示词
- 持久化开发约束
- AI 在当前仓库里的行为边界
常见放法：
- 早期方式：项目根目录 `.cursorrules`
- 当前更常见：`.cursor/rules/` 下拆分多个规则文件
适合写入：命名规范、目录归属、测试要求、禁止改动范围、输出格式要求、提交前验证步骤。
不适合写入：大段背景介绍、频繁变化的临时任务、含糊不清的口号式要求。

### 5.2 示例规则文件
根目录单文件方式：
```md
# Project Rules
- Use TypeScript for new source files.
- Keep public API signatures stable unless explicitly requested.
- Add or update tests for every bug fix.
- Do not modify CI config unless the task explicitly requires it.
- Prefer small, reviewable diffs.
```
目录化方式可使用 `.cursor/rules/coding.mdc`、`testing.mdc`、`architecture.mdc` 等拆分规则。

### 5.3 规则编写原则
- **短**：一句话能说清就不要写一段
- **硬**：必须可执行，不要抽象口号
- **稳**：写长期有效规则，不写一次性需求
坏例子：
```text
尽量写高质量代码
```
好例子：
```text
Do not rename exported types unless the task explicitly requires it.
```

## 6. 常用快捷键
| 快捷键 | 功能 |
|--------|------|
| `Cmd + K` | 行内编辑 / 生成 |
| `Cmd + L` | 打开 Chat |
| `Cmd + I` | 打开 Composer / Agent 入口 |
| `Cmd + Shift + L` | 将选中代码发送到 Chat |
| `Tab` | 接受补全 |
| `Esc` | 拒绝补全 |
| `Cmd + /` | 切换注释 |
| `Cmd + P` | 快速打开文件 |
| `Cmd + Shift + P` | 打开 Command Palette |
说明：不同版本、不同键位映射下，具体快捷键可能略有差异，以本机设置为准。

## 8. 与 CLI 工具对比
| 维度 | Cursor | Claude Code / Copilot CLI / Codex CLI |
|------|--------|---------------------------------------|
| 形态 | GUI 编辑器 | 终端 CLI |
| 上手门槛 | 低 | 中 |
| 操作方式 | 鼠标 + 快捷键 + 编辑器上下文 | 命令 + 提示词 + 终端上下文 |
| 上下文管理 | 自动索引 + `@` 引用 | 自动感知 + 手动指定更常见 |
| 代码修改 | 局部编辑体验强 | 批处理、自动化更强 |
| 多文件任务 | Composer / Agent 直观 | CLI Agent 更适合脚本化 |
| 适合场景 | 日常开发、边写边改、快速对话 | 大规模重构、自动化、远程执行 |
结论：**Cursor 更适合人盯着编辑器连续开发，CLI 工具更适合以任务为单位自动推进。**
最稳妥的方式不是二选一，而是互补：编辑器里写、看、改用 Cursor；终端里批量化、自动化、长链路任务用 CLI。

## 9. 最佳实践
- 善用 `@file`、`@folder`、`@codebase` 缩小上下文范围
- 先用 Chat 分析，再用 Agent 执行
- 一定要配规则文件，让输出贴近仓库规范
- 不同任务选不同模型，别把高价模型用在低价值动作上
- 大任务必须拆小：分析现状 → 给出计划 → 修改子模块 → 验证
- 始终人工 review：检查改动范围、命名一致性、重复逻辑、测试覆盖和文档同步

---
## 10. 最小实践路线
如果你是第一次系统使用 Cursor，建议按这个顺序：
1. 先只用 `Tab`，感受补全质量
2. 再用 `Cmd + K`，练习“范围 + 约束”的写法
3. 再用 Chat，把解释、分析、查找交给 AI
4. 然后给项目加规则，让输出贴近仓库规范
5. 最后再用 Composer / Agent 接多文件任务
按这个顺序，学习成本最低，也最不容易翻车。
